# LEARNINGS – BESS_MAP_DE

- MaStR bulk export is one ~3GB ZIP, but the server supports HTTP Range requests — a stdlib-`zipfile`-compatible seekable file object backed by Range GETs lets you pull just the members you need (central directory + specific compressed member bytes) without downloading the archive. See `scripts/rangefile.py`.
- The `remotezip` PyPI package failed against this specific server ("File is not a zip file") despite the server correctly supporting both suffix and explicit-tail Range requests (verified manually) — root cause not identified, worked around with a ~50-line custom implementation instead of debugging further.
- MaStR's "Stromspeicher" unit category includes ALL storage tech (batteries, pumped-hydro, etc.) and is dominated by count by tiny residential batteries with no street address (hence no lat/long — privacy). Filter on `Batterietechnologie` field present (excludes non-battery storage) + `Bruttoleistung` >= 100 kW to isolate commercial/utility-scale BESS; validated 98% coordinate coverage at that threshold.
- Large per-object-type files (e.g. `EinheitenStromSpeicher`) are sharded into ~28 numbered parts (`_1.xml`...`_28.xml`, ~100k records each) inside the ZIP, not one file — always glob/sort by the numeric suffix rather than assuming a single filename.
- `AnlageStromSpeicher.MaStRNummer` (Anlage-level, has `NutzbareSpeicherkapazitaet` in kWh) is the join key matching `EinheitStromSpeicher.SpeMastrNummer` (unit-level, has power in kW) — capacity and power live in separate files, need a join.
- On this machine, a fresh PowerShell process after `winget install`-ing Python doesn't pick up the updated PATH even after re-reading `[System.Environment]::GetEnvironmentVariable(...,"Machine"/"User")` in the same session — the Microsoft Store `python`/`py` App Execution Alias shadows it. Use the full path (`$env:LOCALAPPDATA\Programs\Python\Python312\python.exe`) directly instead of relying on `python`/`pip` on PATH within a single PowerShell tool call.
- Leaflet's `interactive: false` only works as a top-level `L.geoJSON(geo, {style, interactive: false})` option — nesting it inside the `style` object/function (`style: {..., interactive: false}`) silently does nothing, since `style` is only used for path-drawing attributes (color/weight/fill/etc.), not layer construction options. Easy to miss since there's no error, the layer just stays clickable.
- GitHub's default `GITHUB_TOKEN` pushes do not re-trigger `on: push` workflows (built-in loop protection) — safe to have a bot-commit job and a `push`-triggered deploy job in the same workflow without an infinite-retrigger risk.
- github.com/isellsoap/deutschlandGeoJSON (archived but usable, Unlicense/public domain) has ready-made Germany national + Bundesländer boundary GeoJSON at multiple simplification levels (`4_niedrig` = ~20-100KB, good for web); `properties.name` on the Bundesländer file matches MaStR's resolved `Bundesland` field strings exactly, no name-mapping needed.
- When a background `git push` (e.g. from a manually-triggered Action) diverges the remote from local work in progress, rebase onto `origin/main` rather than force-pushing, and check `git log origin/main` first to confirm the divergence only touches disjoint files before assuming a clean rebase is safe.
- When a chart plots two cumulative series that share an x-axis but cover different time horizons (realized-to-date vs. projected pipeline), extending the "realized" line flat into future years reads as a logical contradiction to users even though the underlying value is technically unchanged — cap/null the series at "now" instead of relying on the value being flat to communicate that it isn't real yet.
- A JS resizable-panel implementation that sets an inline pixel `flex-basis` needs an explicit `flex-basis: auto !important` reset for any responsive breakpoint that changes `flex-direction` (row→column) — otherwise a width chosen on desktop silently gets reinterpreted as a height on mobile.
- Before adding a language toggle to a data-driven page, separate "chrome" (static English/German strings via a `data-i18n` attribute + dictionary) from "data-derived" text (status labels, region names) that needs its own translation map keyed off the underlying data value, not the display string — keeps re-rendering on toggle a matter of re-running one function rather than tracking every dynamic string site by hand.
- When a user request uses a word as overloaded as "sort" (could mean a data table, or map marker z-order, or dropdown ordering), don't guess even under an "act autonomously" default — a wrong guess here means building the wrong feature entirely, not just a tweak. Worth one AskUserQuestion even for users who normally prefer prose-only direction, since the two interpretations aren't a matter of taste, they're different deliverables.
- A single inline `style="display:none; ...other props...; display:flex"` attribute is a real bug pattern, not just messy — CSS resolves duplicate property names left-to-right within one declaration block, so the later one silently wins with no warning. Keep layout properties (flex/flex-direction) that only matter while an element is visible in a CSS class, and toggle only `display` itself via JS/inline style.
- For a scrollable sub-region inside an already-scrollable flex column (e.g. a table with a sticky header inside a sidebar-style pane), the nested container needs `flex: 1; min-height: 0` at every level of the chain, not just the innermost one — otherwise the outer pane scrolls instead of the inner one, and `position: sticky` sticks to the wrong ancestor.
- Once a Chart.js chart has more than one axis-count/dataset-count "mode" (here: MW / MWh / both-with-dual-axis), destroying and rebuilding the chart on every render is simpler and more robust than trying to incrementally `chart.update()` — mutating dataset arrays and scale configs in place to match a changing shape is exactly the kind of state that's easy to leave half-updated.
- When slicing a cumulative series to a user-picked date sub-range (a "zoom" control), slice the already-computed cumulative array for display — never recompute the cumulative sum starting from the new sub-range's first index, or the chart will show a false near-zero baseline instead of the true cumulative total at that point in time.
- Composing a chart legend label by concatenating a translated string with a fixed suffix (e.g. `` `${t('key')} (MW)` ``) only works if the translated string itself is short — check what the base translation actually contains before appending, since a translation written for a standalone context (with its own explanatory parenthetical) will double up when reused as a prefix.
